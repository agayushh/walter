PPTChat — Feature Implementation Roadmap

Current Project State

A ChatGPT clone (Next.js 15 + Neon PostgreSQL + Gemini) with auth, chat UI, file upload.

Critical gaps: /api/chat is empty (no AI responses), file attachments aren't persisted, mic button does nothing, no RAG/voice/MCP.

Feature Overview

Feature Approach Cost
RAG (PDF Q&A) pgvector on Neon + Gemini embeddings via AI SDK ~$0
Voice STT Groq Whisper API (free tier: 2,000 min/day) Free
Voice TTS Google Cloud TTS (free $0-300/mo) or browser SpeechSynthesis Free–$0
MCP (GitHub + Slack) @modelcontextprotocol/sdk — HTTP for prod, stdio for dev Free
Custom Model Training Fine-tune Llama 3.2 3B via Unsloth → deploy on HF Spaces / Ollama / Colab ~$5-10 train (GPU rent), free deploy
Online AI Interview Voice STT + RAG + Gemini streaming Same stack

Goal: This entire project is for experimental / learning purposes. The point is to learn how these technologies work hands-on — not to build something production-ready. Every phase is chosen to teach you something real about ML engineering, full-stack AI, and modern protocols.

Recommended Approach

Stay on AI SDK v5 for the chat/streaming (it already works), add features with standalone SDKs alongside. This avoids migration risk and ships faster. Upgrade to v7 later if needed.

Phase 6: Custom Model Training & Deployment

This is the most educational phase. You'll go through the full ML engineering pipeline — dataset preparation, fine-tuning, evaluation, conversion, and serving. You'll learn LoRA adapters, quantization, GGUF format, and model serving — real skills that apply to production ML work.

What you'll learn

  • How LLMs actually work under the hood (attention, transformers, tokenization)
  • LoRA / QLoRA — parameter-efficient fine-tuning (the industry standard)
  • Dataset formatting for chat models (ShareGPT format, tokenization, chat templates)
  • Quantization — reducing model size with minimal quality loss (4-bit, 8-bit, GGUF)
  • Model serving — REST API, Docker, cloud deployment

Step-by-step training pipeline

  1. Pick a base model — Llama 3.2 3B (small, fits on one GPU) or Qwen 2.5 7B (better quality, needs ~16GB VRAM). Both are state-of-the-art open-source models.
  2. Prepare your dataset — Convert your PDF content into Q&A pairs or instruction-following examples. Format as JSONL with {"instruction": "...", "output": "..."}. Use your project's domain data (chat history, uploaded PDFs) to create a real dataset.
  3. Rent a GPU — Use RunPod or Lambda Labs (~$2-3/hr for RTX 6000 Ada, ~$5-10 total). Unsloth's templates include one-click Jupyter notebooks that connect to these services.
  4. Fine-tune with Unsloth — Unsloth is 2x faster and uses 50% less VRAM than Hugging Face's native trainer. You'll use 4-bit QLoRA, which lets you train a 7B model on just 16GB VRAM. Training takes 1-3 hours.
    • Learn about: LoRA rank (r), alpha, target modules, learning rate schedules
    • Experiment: try different ranks (8, 16, 32) and see how they affect quality
  5. Evaluate — Run inference on held-out test data. Compare your fine-tuned model vs the base model vs Gemini. See if your training actually improved anything.
  6. Export — Convert your LoRA adapter to GGUF format (for Ollama) or safetensors (for Hugging Face). This teaches you about model serialization formats.

Deployment options (free for learning)

Option What you learn Cost
Hugging Face Spaces Docker, Gradio UI, model hosting, inference APIs. You build a web chat UI for your model. Free (CPU)
Ollama (localhost) GGUF quantization, local model serving, REST API. Run your model on your own machine. Free
Google Colab + ngrok Cloud GPU notebooks, tunneling, temp API endpoints. Run your model on a free T4 GPU for ~1 hour. Free
Together AI / Replicate Managed model hosting, auto-scaling, API keys. One-click deploy your LoRA adapter. ~$5 free credits

When to use API keys vs. your own model

Use API keys (Gemini/Groq) for: The RAG pipeline, voice STT/TTS, and the main chat AI. These are plumbing — not the learning target. Using APIs here lets you focus on building the app.

Use your own fine-tuned model for: The core learning experience. The point is to go through training, export, and deployment once so you understand the full stack. Once it's deployed, you can optionally swap it into your chat route to replace Gemini and see how your own model performs.
